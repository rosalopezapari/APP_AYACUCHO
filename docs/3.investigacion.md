# INFORME DE INVESTIGACIÓN - QORY AYACUCHO

## 1. INVESTIGACIÓN DE MERCADO

### 1.1. Contexto Turístico de Ayacucho
- Ayacucho recibe ~500,000 turistas anuales (nacionales e internacionales)
- Principales atractivos: Complejo Arqueológico de Wari, Catedral de Ayacucho, Mirador de Acuchimay, Picanterías tradicionales
- 11 provincias con potencial turístico: Huamanga, Huanta, La Mar, Cangallo, Vilcas Huamán, Víctor Fajardo, Huanca Sancos, Sucre, Lucanas, Parinacochas, Páucar del Sara Sara
- 5 categorías turísticas: Cultural, Natural, Gastronómico, Aventura, Compras

### 1.2. Problemas Identificados
- 70% de turistas llega sin planificación
- 65% gasta más de lo presupuestado
- 80% pierde tiempo buscando información en el lugar
- 75% desconoce pequeños negocios locales
- 60% no usa herramientas digitales para planificar

### 1.3. Oportunidad
- Creciente adopción de tecnología móvil/escritorio en turismo
- Ausencia de una aplicación integral enfocada en Ayacucho
- Demanda de información centralizada y personalizada

## 2. INVESTIGACIÓN TECNOLÓGICA

### 2.1. Lenguaje de Programación: Python
- **Versión:** 3.8+
- **Razón de elección:** Sintaxis clara, amplia biblioteca estándar, multiplataforma, facilidad de mantenimiento
- **Alternativas evaluadas:** Java (más verboso, mayor curva de aprendizaje), C# (dependiente de .NET), JavaScript/Electron (mayor consumo de recursos)

### 2.2. Interfaz Gráfica: Tkinter + ttk
- **Razón:** Viene incluido en la biblioteca estándar de Python, sin dependencias externas
- **Componentes utilizados:**
  - `ttk.TreeView` para listados CRUD con scroll
  - `ttk.Notebook` para pestañas en reportes
  - `ttk.Frame`, `ttk.Label`, `ttk.Button` para layouts
  - `tk.Canvas` para gráficos de barras estadísticos
  - `tk.Toplevel` con `transient()` + `grab_set()` para diálogos modales
- **Tema base:** `clam` (ttk.Style) para consistencia cross-platform
- **Personalización:** `theme.py` con paleta de 12 colores (terracota, crema, azul) y 6 estilos de fuente

### 2.3. Base de Datos: SQLite 3
- **Razón:** Sin servidor, archivo único, incluido en Python estándar
- **Características:**
  - 9 tablas: ciudadano, presupuesto, destino, historial, restaurante, tienda, hospedaje, transporte, ahorro
  - `PRAGMA foreign_keys = ON` para integridad referencial
  - 27 destinos, 14 restaurantes, 14 tiendas, 14 transportes, 14 hospedajes como datos semilla
  - `sqlite3.Row` como row_factory para acceso por nombre de columna
- **Alternativas evaluadas:**
  - MySQL/PostgreSQL: Requieren instalación de servidor, sobrecarga para aplicación local
  - JSON/YAML: Sin capacidad de consultas, sin integridad referencial
  - CSV: Sin estructura de datos relacional

### 2.4. Arquitectura del Software
- **Patrón:** MVC (Modelo-Vista-Controlador) simplificado
  - **Modelos:** `src/models/` — 10 clases (Ciudadano, Presupuesto, Ahorro, Historial, Recomendacion, Destino, Restaurante, Tienda, Transporte, Hospedaje, Exportador)
  - **Vistas:** `src/views/` — 15 ventanas (inicio, registro, login, menú_principal, perfil, exportar, presupuesto, recomendacion, historial, restaurante, tienda, ahorro, transporte, hospedaje, destino)
  - **Controladores:** La lógica de negocio está dentro de los modelos (CRUD estáticos)
- **Módulo central:** `src/database.py` — conexión, creación de tablas, datos semilla
- **Configuración de estilos:** `src/theme.py` — colores, fuentes, estilos ttk

### 2.5. Librerías Utilizadas (solo stdlib)

1. **Integración vertical:** Presupuesto + Destinos + Hospedaje + Transporte + Restaurantes en una sola app
2. **Recomendaciones personalizadas:** Basadas en presupuesto diario, no en ranking general
3. **Planificador de viaje integrado (H12):** Cálculo automático de costo real vs presupuesto
4. **Sistema de ahorro (H8):** Metas de ahorro vinculadas a viajes
5. **Offline-first:** Sin necesidad de conexión a internet (SQLite local)
6. **Gratuito y open-source:** Sin costos de licencia

## 5. VIABILIDAD TÉCNICA

### 5.1. Viabilidad de Desarrollo
- **Costo:** $0 (todo Python stdlib, sin licencias)
- **Tiempo estimado:** 4-6 semanas (una persona)
- **Complejidad:** Baja-Media (CRUD + lógica de negocio simple)
- **Riesgos:** Bajo (tecnología madura, sin dependencias externas)

### 5.2. Viabilidad de Despliegue
- **Distribución:** Archivo único Python, o ejecutable con PyInstaller
- **Requisitos mínimos:** Python 3.8+, SO con soporte Tkinter
- **Almacenamiento:** ~10 MB (app + DB semilla)
- **Sin conexión:** 100% funcional offline

### 5.3. Limitaciones Identificadas
1. **Interfaz:** Tkinter tiene limitaciones estéticas vs frameworks modernos (web/mobile)
2. **Multi-usuario:** Sin soporte de concurrencia (SQLite no está diseñado para alto volumen)
3. **Seguridad:** Contraseñas sin hash (mejorable con `hashlib` en versión futura)
4. **Escalabilidad:** Base de datos local, no centralizada

## 6. CONCLUSIONES
La investigación confirma la viabilidad técnica y la necesidad del mercado de una aplicación integral de planificación turística para Ayacucho. La elección de Python + Tkinter + SQLite permite un desarrollo rápido, sin costos de infraestructura, con resultados funcionales y mantenibles.
